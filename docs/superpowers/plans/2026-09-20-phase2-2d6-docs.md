# Phase 2 stage 2d-6 — the docs consolidation and the Go-boundary ADR

**Goal.** Bring the standing documentation into line with the tree Phase 2
leaves behind, and record the two decisions that shaped it as durable decision
history. After 2d-4 deleted `apps/proxy/live_proxy/`, `CLAUDE.md` — the
instruction set every future agent reads before touching this repository —
describes a relay that does not exist, in forty-seven passages. `CONTEXT.md`,
the glossary `docs/agents/domain.md` sends every exploring agent to *first*,
has no Phase 2 term at all and defines "Relay" as one uWSGI process running
Django. This PR is the consolidation pass the spec scheduled for exactly this
moment, plus **ADR 0006**, plus the ledger and worklist edits the standing
rules require in the same PR. It is the last PR of Phase 2.

**Architecture.** Django 6 + DRF control plane; a stdlib-only Go relay
(`relay/`) serving the whole live surface through nginx since stage 2d-3; a
Python uWSGI relay narrowed to VOD, catch-up and `timeshift.php`.

**Tech stack.** Markdown, YAML, Python 3 (three one-line logger renames, three
test strings and two stale comments), gh-aw.

**Spec.** `docs/superpowers/specs/2026-09-09-phase2-go-relay-design.md`,
§ Stage 2d `### Deletion order — one PR each` **entry 6**, as amended by
**A10** (A10.8, A10.10, A10.17), **A11.5** (which moved one of entry 6's items
to 2d-1), **A12.4** (the logger rename handed here), **A13**, **A14** (2d-4's
R15/R18 handovers) and **A15** (2d-5's R12/R14). This plan's own amendment is
**A16**, in Appendix G, and it is the last one: it closes the spec.

**Branch.** `migration/phase2d-docs`, as the spec names it. The `migration/**`
prefix runs every Playwright project plus both bash suites, path filters
bypassed — which this plan **relies on** rather than merely accepts (R9).

## Global Constraints

Numbered so a task step can cite one. **A conflict between a constraint and a
task step is a STOP and report, never a judgement call.**

1. **Anchor every command** with an absolute path or a leading
   `cd <your worktree> &&`. The shell's cwd is shared or correlated across
   concurrent agents (`CLAUDE.md` § Repository and direction).
2. **`set -o pipefail` on every pipeline whose emptiness or exit status you
   intend to read**, and never `2>/dev/null` a git query you will interpret.
   `git show "${ref}:path"` with braces, always.
3. **Stage and commit in separate Bash calls**, and write the commit message
   with the Write tool, committing with `git commit -F <file>`.
4. **No behaviour change.** The only executable edits in this PR are three
   `logging.getLogger()` names, three `assertLogs`/`assertNoLogs` strings and
   two stale comments (R2). Nothing else under `apps/`, `relay/`, `docker/`,
   `dispatcharr/`, `core/`, `scripts/` or `frontend/` is touched. If a step
   appears to need one, STOP. **`app_name = "live_proxy"` in
   `apps/proxy/stream_routes.py` is a URL namespace, not a stale string**, and
   renaming it would break `proxy:live_proxy:stream` and 2d-2's
   byte-identical-`name=` gate.
5. **No `docker/` file is edited**, including comments — R11 names the one
   stale comment this constraint deliberately leaves behind.
6. **No `.lock.yml` is hand-edited, ever.** The four that change are the
   output of a bare `gh aw compile` and are committed exactly as it writes
   them (R5).
7. **No floor file is touched.** `scripts/coverage_live_path.floor`,
   `.floor.modules`, `.coveragerc`, `coverage_relay_go.floor` and
   `.floor.packages` are 2d-5's and 2c-9's. This PR runs neither coverage
   gate and writes neither floor.
8. **Every number in a shipped file is measured, and measured numbers reach
   the appendices as ARGUMENTS, never as literals** (2d-4's Appendix K lesson,
   restated as A16.8).
9. **A channel UUID and a provider URL are secrets.** Neither appears in a
   log, a test, a commit message or the PR body.
10. **Every appendix has a `--check` mode and Task 0 runs all of them.** An
    appendix that cannot verify its own anchors without writing is not
    finished.
11. **Deleting a sentence is a disposition, not a tidy-up.** R1's table gives
    every CLAUDE.md passage it lists a disposition — rewrite, delete, or
    keep-as-history with a stated reason. (The table is the count; this
    constraint deliberately quotes no number, because the count moved twice
    under review and every place that restated it had to be chased.)
12. **A whole-read means the whole FILE, not the sections a grep pointed at.**
    R1's method is applied to `CLAUDE.md` *and* `CONTEXT.md`; the fix round's
    single largest finding was a `CONTEXT.md` section that no `live_proxy`
    grep and no §-scoped read could reach (R1b).

### R2 — the A12.4 logger rename is made here, it is THREE loggers, and it is not a behaviour change

**The question the brief poses**: the spec assigns a one-line code change to a
docs PR. Make it, or hand it to a follow-up?

**Measured, and the measurement changes the question.** There are three
`live_proxy`-named loggers on the post-2d-4 tree, not one:

```bash
$ grep -rn 'getLogger("live_proxy' --include='*.py' .
apps/proxy/ts_admin_views.py:43:logger = logging.getLogger("live_proxy.views")
apps/proxy/next_source.py:38:logger = logging.getLogger("live_proxy")
apps/proxy/stream_routes.py:42:logger = logging.getLogger("live_proxy")
```

The second is 2d-1's, put there for the same reason and never listed. **The
third is 2d-4's own**, created by its Appendix O, and its comment there reads:

> Renaming it once the directory behind the name is gone is 2d-6's, **which
> now has TWO sites** — this one and `apps/proxy/ts_admin_views.py`'s (spec
> Amendment A12.4).

— so 2d-4 hands the item on while itself miscounting it, missing
`next_source.py`. Renaming any subset leaves the tree with a `live_proxy`
logger and the follow-up still owed, which is the worst of every option.

**`app_name = "live_proxy"` at `stream_routes.py:85` is NOT renamed.** It is
the URL namespace 2d-4 deliberately preserves so `proxy:live_proxy:stream`
stays reversible and 2d-2's byte-identical-`name=` gate keeps holding. A sweep
that treated it as one more stale string would break a route name, silently,
in a PR whose gate does not resolve URLs.

Three tests bind the **string**, not the logger object:

```bash
$ grep -rn 'assertLogs("live_proxy"\|assertNoLogs("live_proxy"' --include='*.py' .
apps/proxy/tests/test_next_source_api.py:660
apps/proxy/tests/test_next_source_edges.py:349
apps/proxy/tests/test_next_source_resolution.py:352
```

`apps/proxy/tests/test_admin_control_views.py` binds `views.logger`, the
object, at five sites and needs no edit — so the breakage is one-sided, and a
rename that only ran `apps.proxy` after editing `ts_admin_views.py` would look
green and break on the other file.

**It is behaviour-preserving, and that is measured rather than assumed.**
`dispatcharr/settings.py:563-616`'s `LOGGING` declares `apps.proxy` with
`handlers: ["console"]`, `level: LOG_LEVEL`, `propagate: False`, and `root`
with the same handler at the same level. A logger named `live_proxy` matched
no `loggers` entry and fell through to `root`. Handler and effective level are
therefore **identical** before and after; the only observable change is the
`{name}` field the `verbose` formatter prints. This is the fact that makes the
edit safe in a docs PR, and it is exactly the fact a "rename a logger" edit

### R10 — the ADR is number 0006, and D2 and D3 are ONE decision

`ls docs/adr/` gives `0001`…`0005`; the next free number is **0006**.
Filename: `0006-the-go-relay-keeps-its-state-in-memory-and-the-cutover-is-hard.md`,
following 0005's sentence-as-title convention. Written in 0005's exact idiom:
`# N. Title`, `Date:`, `## Status`, `## Context`, `## Decision`,
`## Consequences`.

**The substantive ruling is the framing.** The spec presents D2 ("memory not
Redis") and D3 ("hard cutover, no canary") as two decisions. They are one, and
writing the ADR is what made the dependency visible: a canary needs two
implementations serving the same channel set concurrently, and two
implementations that share no state cannot do that — a viewer whose second
request landed on the other relay would find no channel, no buffer and no
client registry. Choosing memory is choosing one live relay process at a time;
choosing one process is what makes the lease unnecessary. An ADR that recorded
them separately would leave the next person free to "add a canary later",
which is not available without undoing D2.

The ADR also records the three couplings the cutover found, which currently
live only as PR-local rulings in two plans:

- **F1, the `auth_request` resolver coupling** (2d-4's R6):
  `apps/proxy/authorize_views.py`'s `_surface_for()` resolves the tune URI
  through Django's **own** urlconf and keys on the resolved view's `__name__`,
  so Django must keep live URL patterns it no longer serves. They survive in
  `apps/proxy/stream_routes.py`. Deleting them with the package would have
  403'd every live tune behind nginx.
- **`proxy_set_header` replaces, it does not merge** (A13): a location
  declaring any of its own inherits none of the server-level ones. Uncaught,
  every live client's `ip_address` becomes nginx's address while VOD and
  catch-up keep reporting correctly.
- **An inherited `proxy_connect_timeout`** (A13.11): a `proxy_pass` location
  picks up simple server-level directives its `uwsgi_pass` predecessor never
  consulted. The general rule — *when a location changes directive family,
  audit the server block for the new family* — is the transferable part.

Four corrections the fix round made to the ADR's own text, each measured:

- **F1's consequence overstated what survives.** The first draft said the
  route declarations are "reached by the inline fallback in a deployment
  without nginx". 2d-4's Appendix O makes both callables **501 stubs that log
  a warning and authorize nothing** — "These two callables therefore exist to
  BE RESOLVED, never to be called" — and the inline `authorize_stream`
  fallback that lived beside them in `live_proxy/views.py` went with the
  package. An ADR is a durable authority and that clause would have sent a
  future reader looking for an authorization path that does not exist.
- **"every row had a passing Go-side pin"** is true of 28 of 30. Rows 26 and
  27 are white-box-only and carry a `retired:` sentinel instead, which the
  matrix's own header — the file Appendix F edits — says. "Held to parity"

- **"a revert of a 101-file deletion"** is neither of the two real figures:
  the package is 101 files, of which 97 are deleted and four `git mv`'d, and
  2d-4's own File structure counts 106 deletions, 4 renames and 43
  modifications.
- **"What remains on the live path is nothing"** is immediately followed by a
  list including the provider-slot counters and Django's assignment keys,

Plus one structural fix: every other ADR's `## Status` is the bare word
`Accepted` (`for f in docs/adr/000[1-5]*.md; do sed -n '5,8p' $f; done`), so

````markdown
# 6. The Go relay keeps its state in memory, and the cutover is hard

Date: 2026-09-20

## Status

Accepted

## Context

This builds on [ADR 0005](0005-the-relay-is-chosen-by-name-once-per-tune.md),
which is unchanged: authorization is still Django's decision, made once per
tune, and provider slots still live in Django. What follows is the two
decisions Phase 2 made that ADR 0005 did not anticipate, and the three
couplings the cutover found.

Phase 1 split the relay into its own uWSGI process without moving any relay
internals: the same Django code, the same urlconf, the same Redis keys, a
different listener. Phase 2's question was whether to reimplement the live
byte path in Go, and the two sub-questions that decided its shape were **where
the new implementation keeps channel state** and **how it takes over from the
old one**.

Both had an obvious answer that was wrong for the same reason, and the reason
is the process count.

**On state.** The Python relay kept everything in Redis — the ownership lease,
the channel metadata hash, the client sets, the switch requests, and the video
bytes themselves in a ring buffer of ~256 KB chunks. None of that was a
storage decision. It was a *coordination* decision forced by four API uWSGI
workers plus the relay's one all serving the same channel: no channel state
could live in Python memory because there was no single Python process that
owned a channel. The ownership lease existed to elect one of them per channel,
and it was time-bounded rather than fenced — `StreamBuffer.add_chunk()` wrote
with no ownership check and no fencing token, so two owners interleaved chunks
at alternating monotonic indices and readers decoded a spliced stream with
every check passing. Phase 0 recorded that as a carried constraint the
extracted relay must not recreate.

The straightforward port keeps the Redis shapes and writes Go against them.
That reproduces the lease, and with it the defect, in a language where the
fencing fix would have been easier — and it pays Redis's round trip and its
serialisation for every chunk of every stream, which is the single largest
cost on the byte path and the thing Phase 3 was created to remove.

**On cutover.** ADR 0005 built a canary mechanism and this ADR's phase is the
one it was built for: `X-Relay-Name` on the authorize response, copied into
`$relay_name` by `auth_request_set`, mapped to an upstream *group*. A second
Go relay taking a subset of channels was supposed to be one map entry, one
`upstream` block and a Django-side assignment table. The temptation is to use
it: run both relays, move ten channels, watch, move the rest.

## Decision

**The Go relay keeps its channel state in process memory, not in Redis**
(spec D2), **and the cutover is a hard switch of nginx's live locations with
no canary period** (spec D3).

The two decisions are one decision. A canary needs two implementations serving
the same channel set concurrently, and two implementations that share no state
cannot do that: a viewer whose second request landed on the other relay would
find no channel, no buffer and no client registry. Choosing memory over Redis
is choosing to have exactly one live relay process at a time, and choosing one
process is what makes the lease unnecessary.

Concretely:

- `relay/channel`'s `Manager` holds one `Channel` per live channel behind one
  mutex. Ownership is a map entry. There is no lease, no heartbeat, no orphan
  sweep and nothing to fence.
- `relay/buffer`'s ring is per-channel and in-process: a 300-chunk /
  76,760,400-byte cap and the same 60-second retention the Python ring had,
  whichever binds first, sized from `BUFFER_CHUNK_SIZE` on the `next-source`
  answer rather than from a Go-side constant, so a `proxy_settings` edit still
  moves it.
- The client registry is likewise a map with no TTL, no heartbeat and no ghost
  sweep, because with one process a client entry cannot outlive the goroutine
  that made it.
- The Go binary opens no Postgres connection and no Redis connection and links
  no driver for either. `scripts/check_go_stdlib_only.sh` is the mechanical
  backstop, and there is no `relay/go.sum` at all — `go list -m all` prints
  exactly the one module.
- At stage 2d-3 four nginx locations moved from `uwsgi_pass` to
  `proxy_pass http://relay_go` in one commit — the three byte-path locations
  plus `^~ /proxy/relay/` — and stage 2d-4 deleted `apps/proxy/live_proxy/`.
  There was never a window in which both relays served live traffic.

What makes a hard cutover acceptable rather than reckless is that the
*evidence* was gathered ahead of it instead of during it: the relay parity
matrix enumerates every externally-observable live-path behaviour, each row
carrying the source it was derived from and a test that pins it, and every row
was held to parity before any location moved: 28 of the 30 by a passing
Go-side pin, and the other two — `server.py`'s greenlet topology and
`_execute_redis_command`'s swallowing — by being white-box-only properties of
the implementation being deleted, which carry a `retired:` sentinel because
there is no Go source to point a citation at. Deliberate divergences (spec
D5's two) are recorded as rows, not discovered as incidents.

## Consequences

- **The ownership lease defect is retired, not fixed.** There is no analogous
  defect in a single-owner-per-process design, so Phase 0's carried constraint
  closes by elimination. `e2e/COVERAGE.md` keeps the trace of the one grey-box
  row that could never provoke it from outside the container, as the record of
  a gap that closed the same way.
- **A relay restart drops every live viewer, and nothing makes that gradual.**
  There is no second relay to bleed connections onto. D6's fifteen-second
  drain (a client grace, a concurrent channel teardown that releases every
  provider slot, then `http.Server.Shutdown`, with three seconds reserved for
  the events flush) bounds the damage; it does not remove it. `relay-go`
  measured ~17.3s from `supervisorctl restart` to a fresh tune's first byte.
- **A rollback is a revert of the nginx flip, and only while the Python relay
  still exists.** Between stage 2d-3 and stage 2d-4 that was a one-file
  change. After 2d-4 it is a revert of 106 deletions, four renames and 43
  modifications: the package was 101 files, 97 deleted and four `git mv`'d
  into the Go module, plus nine standalone paths. The window was
  deliberately left open across one merge and deliberately closed.
- **ADR 0005's canary machinery is still there and is still right — it just
  does not apply at this grain.** `$relay_name` is set per relay-bound
  location from one process-wide `settings.RELAY_DEFAULT_NAME`, so the map can
  say "this deployment's relay is X"; it cannot say "these four locations
  resolve differently than those six". (`docker/nginx.conf`'s own comment
  says "five"; measured, it is four `proxy_pass http://relay_go` against six
  `uwsgi_pass $relay_upstream`, with two more naming `relay_py` literally and
  consulting no map at all.) The four flipped locations name
  `relay_go` literally and consult no map. The mechanism's real users are a
  future per-channel assignment table and horizontal scale-out, neither of
  which this phase needed.
- **Django still owns the live URL patterns even though Django no longer
  serves them.** `apps/proxy/authorize_views.py`'s `_surface_for()` resolves
  the tune URI through Django's own urlconf and keys on the resolved view's
  `__name__`, so the authorize hop for a URL Django cannot resolve fails
  closed. Deleting `stream_ts` and the two XC live patterns with the rest of
  the package would have 403'd every live tune behind nginx. They survive in
  `apps/proxy/stream_routes.py` as route declarations that exist **to be
  resolved, never to be called**: both callables log a warning and answer
  `501`, and the inline `authorize_stream` fallback that used to sit beside
  them in `live_proxy/views.py` went with the package. A deployment without
  nginx does not reach them either — the Go relay serves those routes on its
  own port, and Django answering 501 is how it says so.
- **`proxy_set_header` replaces, it does not merge.** A location that declares
  any `proxy_set_header` of its own inherits none of the server-level ones, so
  the three byte-path locations re-declare all six. Uncaught, every live
  client's `ip_address` silently becomes nginx's own address while VOD and
  catch-up — still on `uwsgi_pass`, a different directive family with
  different inheritance — keep reporting correctly. `^~ /proxy/relay/`
  deliberately re-declares none.
- **A `proxy_pass` location inherits simple server-level directives that its
  `uwsgi_pass` predecessor never saw.** `proxy_connect_timeout` was set at
  server level for an unrelated `proxy_pass` elsewhere in the same block; the
  flipped locations picked it up silently and exceeded the modular role
  split's 70s budget. All four now set it explicitly. The general rule: when a
  location changes directive family, audit the *server* block for the new
  family, not only the location.
- **Buffering is a per-family decision.** `proxy_buffering off` on the three
  Go-bound byte paths, `uwsgi_buffering off` on the six still speaking uWSGI,
  and nothing on `^~ /proxy/relay/`, which serves short JSON. The historical
  bug was the mirror image of the new hazard — `proxy_buffering off` written
````
