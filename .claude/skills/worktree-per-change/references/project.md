# Project specifics: Dispatcharr (D10Scot/Dispatcharr)

Rewrite this file when porting the skill. Everything in `SKILL.md` is generic; everything here names this repository.

- **Root checkout:** `/Users/dion/git/Dispatcharr`, branch `main`. `origin` is the fork (push here); `upstream` is fetch-only.
- **Worktree directory:** `.worktrees/<id>` under the root checkout (kept out of `git status` by `.git/info/exclude`, not `.gitignore`); this is `<worktree-dir>` in `SKILL.md`. Branch names in use: `fix/<PR-id>-<slug>`, `docs/<slug>`, `feat/<slug>`, `migration/<slug>` (the last runs the full E2E matrix by branch name).
- **Base SHA:** cut from `origin/main`; plan line numbers were opened at the seed SHA the plan's header names, so re-grep every anchor.
- **Shared test container:** `dispatcharr-testrunner`, bind-mounted read-only at `/repo` from ONE worktree. The `PostToolUse` hooks on `Write|Edit` (`.claude/settings.json`) always use that container, whatever `DISPATCHARR_TEST_CONTAINER` an agent exported: hooks run in the harness's environment, not the agent's shell. `run-affected-tests.sh` derives the repo root from the edited file and refuses loudly when it differs from the container's `/repo` mount. The commit gate (`pre-commit-tests.sh`) anchors on its cwd, or a parsed `cd <dir> &&` / `git -C <dir>`, and on a mismatch only warns and skips the backend tests. `run-go-checks.sh` runs on the host and uses no container. See which tree it holds with `docker inspect dispatcharr-testrunner --format '{{range .Mounts}}{{if eq .Destination "/repo"}}{{.Source}}{{end}}{{end}}'` (filtered by destination, as the hook does: the mount list also holds the database volume, in no stable order).
- **Your own container** for test runs you launch yourself: `DISPATCHARR_TEST_CONTAINER=<name> DISPATCHARR_TEST_DB_VOLUME=<name>-db CLAUDE_HOOK_REPO_ROOT=<worktree> <worktree>/.claude/hooks/start-test-container.sh`, then run labels the way `.claude/hooks/run-affected-tests.sh` does (Redis flushed before each run, whole package). Labels per `python scripts/ci_backend_test_labels.py`. Remove the container and volume by name in the tidy-up.
- **E2E stacks:** private container, network, port, upstream AND image tag (`DISPATCHARR_E2E_IMAGE=dispatcharr-e2e-<id>:local`); the shared `dispatcharr-e2e:local` tag is stale and `scripts/e2e_up.sh` reuses it silently. Never pass `--down` or `--reset` to `scripts/e2e_up.sh` (it removes the shared `e2e-upstream` provider); tear down with `docker rm -f` and `docker network rm` on your own names only, and never touch `dispatcharr-e2e`, `e2e-upstream` or `dispatcharr-testrunner`.
- **Occupancy container names:** each plan's measurement task names the container it creates; that name is the `docker ps --filter name=` argument.
- **Scratchpad:** the session scratchpad directory the harness names; scratch exports and scratch repositories live there, never under the root checkout.
- **Known incident (2026-09-25, #489):** `GIT_DIR=<shared .git> GIT_WORK_TREE=<export> bash scripts/run_metrics_tests.sh` made the metrics fixtures `git init` into the shared repository. Repair, if it recurs: `git config --unset core.worktree`, `git update-ref refs/heads/main origin/main`, `git reset` (index only), `git checkout -- <paths that differ>`.
- **Untracked by ruling:** `docs/comparisons/` stays untracked in the root checkout; do not add it.
