# Project specifics: Dispatcharr (D10Scot/Dispatcharr)

Rewrite this file when porting the skill. `SKILL.md` is generic; this file names this repository.

- **Where plans and specs live:** `docs/superpowers/specs/<date>-<slug>-design.md` and `docs/superpowers/plans/<date>-<slug>.md` (the directory name is historical). Analyses go in `docs/superpowers/analysis/`. A plan's header states its goal, its seed SHA, its global constraints, an overlap table with sibling plans, and one section per PR with a PR-description draft; appendices are diff hunks against the seed SHA.
- **Authorities a plan must cite:** CLAUDE.md, `CONTEXT.md`, the phase spec it serves, the ADRs under `docs/adr/`, and `docs/relay-parity-matrix.md` for anything on the live path. Plans carry the header line "implement this plan task by task with subagents, per CLAUDE.md § Delegation for phase work".
- **PR-description drafts inside a plan** name issues as "#N (planned in PR X-n)", never with a closing keyword; the implementation PR that lands the fix carries `Closes #N.` (one keyword per issue). Thirteen issues were once closed by merging plan PRs that quoted their future descriptions.
- **Models:** planner on `opus` (`fable` for a plan that rules on a design question). Reviewer: `fable` is CLAUDE.md's default; the cadence the user set for the 2026-09 fix programme, to conserve fable credits, is `opus` for rounds one and two and `fable` from the third, and that is what runs today. `sonnet` never plans: every sonnet plan draft from Phase 1 PR 3 onward failed its first review and was rewritten on opus.
- **Rulings:** the user's rulings (recorded in the orchestrator's scratch `rulings.md`) override a plan's default; the dispatch names them.
- **The PR opens as a draft and stays a draft until the internal review passes:** `gh pr create --repo D10Scot/Dispatcharr --draft --base main --title "<title>" --body-file <file>`; the body ends with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`. Reason: the pr-review bot reviews each PR **once**, on the first non-draft head it sees, and never again unless its review is dismissed. A PR opened ready spends that one review on the unreviewed head and every fix round after it lands without a bot pass. Marking ready is the merge gate's first action after the internal PASS (`pr-merge-gate`), so the bot reviews the head that merges.
- **Silent planner:** allow at least 2.5 h before relaunching; check the scratchpad (`ls -lt`) and `ps` for `go test` / `manage.py test` first. If a relaunch is unavoidable, give it a different worktree and tell the reviewer to compare both from the start.
- **Metrics dashboard:** a plan that closes a ledger issue, adds a `test.fail()` pin or ticks a Done log also updates `metrics/curated/` in the same PR; `python -m metrics.build --validate-only`.
