# Project specifics: Dispatcharr (D10Scot/Dispatcharr)

Rewrite this file when porting the skill. `SKILL.md` is generic; this file names this repository.

- **Repository flag:** every `gh` call carries `--repo D10Scot/Dispatcharr`; without it `gh` resolves to the upstream public tracker. Base branch is `main`.
- **Drafts:** every PR from `plan-review-fix` or `implement-review-escalate` arrives here as a draft that has passed its internal review, because the bot below reviews a PR once, on the first non-draft head, and a PR opened ready would spend that review before the fix rounds. `gh pr ready` is this gate's first write.
- **Review bot:** the `pr-review` gh-aw workflow (`.github/workflows/pr-review.md`, model `kimi-k3`). It runs on every non-draft `pull_request` event from a same-repo head and reviews each PR **once**: a `prior-review` job checks for an existing `github-actions[bot]` review carrying `Verdict:` and skips the agent when one exists, so a fix push after its review gets no second review unless that review is dismissed. It posts inline comments tagged `[blocking]`, `[should-fix]`, `[question]` and always ends with a `COMMENT` review whose body carries a `Verdict:` line; `Verdict: ready to merge` is the passing text, `Verdict: changes needed` the other.
- **Main ruleset:** required status checks are `agent` and `safe_outputs` (the bot's jobs) plus the aggregates `E2E result`, `Lifecycle result`, `Backend result`, `Frontend result` and `Go result`; `required_review_thread_resolution` is on; `strict_required_status_checks_policy` requires the branch up to date. A skipped heavy job on a required run fails its aggregate; only a docs-only diff (the `changes` detector) is forgiven.
- **Thread ids:** `gh api graphql -f query='{repository(owner:"D10Scot",name:"Dispatcharr"){pullRequest(number:<n>){reviewThreads(first:50){nodes{id isResolved path line comments(first:1){nodes{body}}}}}}}'`.
- **Known flakes (2026-09-25):** the seeded e2e project's 3-per-minute login throttle (#474; three hits in one day, `login as e2e-w1-… failed: 429`); the pr-review bot's `safe_outputs` step failing on the gh-aw installation's API quota after several simultaneous runs (recovers with `gh run rerun <id> --failed` after the hourly reset). A cancelled e2e run has been misread as a failure once; check `conclusion` before acting.
- **Plans, specs and memos** carry no `close`/`fix`/`resolve #N` anywhere in the body ("close #86" mid-sentence also links; `Closes: #N` and `owner/repo#N` forms link too). A docs change that fixes a docs-drift issue is a fix and carries `Closes #N.` (#501 closed #476 that way). After merging a PR meant to close nothing: `gh issue list --repo D10Scot/Dispatcharr --state closed --limit 20 --json number,closedAt,title` and reopen with a comment what the merge closed.
- **Stacked PRs:** `gh pr list --repo D10Scot/Dispatcharr --json number,baseRefName` before merging any PR that is a base; `gh pr edit <child> --base main` for each child first (#236, #237 and #239 were closed, not retargeted, when their base branch was deleted).
- **Post-merge on main:** the push workflows are path-filtered, so which of them fire depends on the diff: `docker-build.yml` (publishes `:latest`), `ci.yml`, `vuln-scan.yml`, `codeql.yml`, `e2e-tests.yml` and `metrics.yml` skip a docs-only merge, while backend, frontend, Go and lifecycle tests, Lint and Scorecard run on every push; check the runs that exist for the merge SHA rather than a fixed list. A base-image change is proven end to end by dispatching `base-image` → `ci` → `vuln-scan` → `go-tests` and reading each run's conclusion by id (a `gh run list --limit 1` right after dispatch can pick up a stale run).
- **Worktree and branch cleanup:** root checkout `/Users/dion/git/Dispatcharr`; `git worktree remove .worktrees/<id> && git branch -D <branch>` (a removal that refuses on a dirty tree is the signal to look, not to force).
- **Ledger:** the orchestrator's scratch `impl/ledger.md`, one row per PR; status becomes `MERGED <sha>`.
- **Serial merge driver:** a queue file plus a loop that, for the head of the queue, checks `mergeable` (re-queues DIRTY), updates the branch if BEHIND, re-runs a rate-limited bot run once, waits for `MERGED`, then advances. Scripts from 2026-09-25 live in that session's scratchpad (`impl/merge-driver-4.sh`, `impl/ready-stager-3.sh`) as a reference shape, not as tooling to reuse blindly.
